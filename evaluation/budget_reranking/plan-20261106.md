# 预算感知的按需重排：执行前方案（2026-11-06）

本文件在新增门控代码、阈值搜索和本轮真实计时之前保存。历史 v0.13 开发结果已知：Hybrid 最终证据覆盖 35/41，BGE 37/41，CPU 重排很慢；这些不是独立验证结果。研究目标是判断重排前信号是否能保留全量重排的证据收益并减少执行次数，不预设门控有效。

## 固定输入与对照

- 语料：只读 `evaluation/support_corpus_large`，固定 102 份文档、2,212 个 sections 500/80 分块。
- 问题：只读 `work/human-review/20261028/review-corrections-20261028T075633Z/questions.current.jsonl`，47 道已人工确认开发题；41 道可回答题参与检索，6 道边界题单列跳过。审核来源及备注不改写。
- 原始 8 题测试集不加载题文、不评分、不参与阈值选择；仅保存整个原始候选文件的保护哈希。
- 固定本地 E5-small、BGE-base 的现有提交和模型文件校验；CPU float32、4 线程、batch=8、max_length=512；不下载模型、不调用 API、不使用 GPU，不触及其他项目或既有训练目录。
- 两路各 50、等权 RRF k=60、融合后 50、Top-5、neighbors、8,000 正文字符预算。三组：none、all、adaptive。唯一处理差异是是否实际调用 BGE。

## 预先限定的门控搜索空间

只使用融合后候选已有的检索分数与两路排名，入口不接受问题 ID、金标或评测对象。拒绝已经含 BGE 分数的候选。

1. `overlap`：两路 Top-5 的共同分块数。共同 Top-5 块必在等权 RRF Top-50 内；门控条件 `overlap_count < threshold`，阈值 `[0,1,2,3,4,5,6]`。0 为从不，6 为全部。
2. `margin`：`(RRF[0]-RRF[4])/RRF[0]`（不足 5 个候选按末位）；门控条件 `margin <= threshold`，阈值 `[0,0.002,0.005,0.01,0.02,0.05,1.01]`。

仅搜索这 14 个单特征规则，不组合、不按题目或主题定制规则、不增加模型。开发金标仅用于离线选择阈值与评价，不进入线上特征。历史 BGE 分数仅供**离线结果回放**，不会被当作免费信号或计时结果。

## 选择与防止结果包装

- 主规则：在开发集上保留 all 组每道最终完整覆盖题、不新增相对 none 的最终完整覆盖损失，且 Top-5 完整覆盖数量不低于 none，满足时取触发最少规则；并列优先 overlap、较小阈值。全量端点保证可行。节约目标为触发率不高于 50%；达不到即如实报告。
- 同时完整输出 25%/50%/75%/100% 调用预算下的规则前沿：先满足预算且不损失 none 最终完整题，再最大化最终完整覆盖、Top-5 完整覆盖，再最少调用。不得只展示获胜阈值。
- 保存每个阈值的逐题决策、增减题目和选择过程。在开发集做 5 折 group_id 分组交叉验证：固定按组名排序轮转分配，训练折选择上述主规则，验证折仅评分；另存跨折合并结果、阈值稳定性。属于开发内部诊断，不充当未见测试性能；历史已查看的开发集仍有适配偏差。
- 主规则选择文件写入后冻结并校验哈希；真实运行不重新调参、不按真实计时结果改阈值。若重跑排序与回放有差异，保留差异而不修饰结果。

## 指标、真实计时与输出

- 完整证据覆盖：每个题目的所有审核证据范围均被原文字符区间并集完整覆盖。分别计算种子 Top-5 与最终 neighbors 上下文的完整题数/41；额外保存逐条 anchor 覆盖和部分覆盖率，不以文档命中代替。
- 触发率=实际 BGE 调用查询数/41；另报打分 query-chunk 对数、覆盖收益、相对 none/all 新增损失。覆盖不是生成答案正确率。
- 回放阶段：读取冻结 v0.13 before/after，校验问题语义、语料、分块和候选身份；保存所有阈值结果。只计回放开销，不据此推断实际延迟。
- 真实阶段：独立新目录、新向量缓存；初始化、模型校验、冷建库和每组 1 次暖机另列。41 题×3 组×3 重复；逐题按 `(题序+重复序)%3` 轮换组顺序。每组每次独立执行 E5 查询编码、检索、（门控）、实际 BGE（如触发）、版本可用块筛选与上下文装配。查询/BGE 无结果缓存；门控计算和分支包含在端到端计时内，写盘和金标评分排除在外。
- 保存 perf_counter 原始阶段毫秒和总毫秒，以所有 123 次/组的线性插值分位数报告真实 P50/P95，另报均值、逐重复分位数、门控开销和 BGE 开销。串行本机 CPU 观测不代表并发服务性能；重复不增加独立问题数。P95 可能无法降低，须如实展示。
- 所有新增结果独立保存，历史 corpus/reports/review/work 中相关实验、既有未跟踪目录先哈希保护，完成后复验；代码/配置/模型/输入指纹保留。必要回归测试与显式真实模型集成测试分别报告。
- 准备独立验证候选与原文审核包：来自新增主题/版本，全部 `unreviewed`，助手逐字检查另存 `assistant_checked`，真实人工审核保持 pending；冻结规则后准备，不运行候选检索评分。不得把候选规模当正式 benchmark 或把助手检查冒充人工审核。
