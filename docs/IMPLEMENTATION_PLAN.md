# 技术支持助手实施计划

## 场景选择

面向 AI 应用开发实习，选择「版本感知的开发者技术支持与故障排查助手」，首个知识域为 FastAPI 官方中文文档。它便于复核答案、构造相邻技术概念的困难检索任务，也能展示文档摄取、版本约束、证据评测和故障定位能力。场景选择是基于本项目可实施性作出的判断，不代表招聘市场统计结论。

| 候选 | 优点 | 当前取舍 |
|---|---|---|
| 研究生培养制度 | 已有两份资料，适用对象明确 | 当前覆盖窄，与目标岗位的技术工作关联较弱 |
| 通用企业内部制度 | 常见业务需求 | 缺乏真实、可公开的企业资料及用户反馈 |
| 开发者技术支持 | 官方资料、示例代码可核验，失败可以复现 | 本轮选定；先限定 FastAPI，防止范围扩散 |

## 验收范围

1. 重建可运行的仓库 `.venv`，保留旧环境备份，跑通已有测试。
2. 获取 FastAPI 0.110.0 / 0.115.0 的官方文档快照，固定上游 commit、许可证、文件哈希和代码引用；保留原有培养管理 PDF。
3. 实现章节分块、产品/版本过滤；未指定版本且存在多个版本时澄清；未知版本拒答，不静默改用其他版本。
4. 引用仅返回实际引用的证据，校验引用编号、引用完整性；明确区分结构校验与语义支持核验。
5. 实现证据范围标注、文档级与证据级检索指标、回答/拒答状态评测、每题原始记录与数据/配置指纹。
6. 构建有原文锚点的候选评测数据，保持未人工复核状态；正式评测必须显式区分开发集与测试集。不得伪造人工审核或效果数字。
7. 实现稳定文档身份、版本内替换、向量缓存和索引失败回滚；补充有意义的回归测试。
8. 提供轻量演示页面，展示版本选择、引用原文和请求耗时；以零密钥模式验证完整链路，凭据就绪后才运行真实模型并保存报告。

## 执行顺序

环境与场景语料 → 证据评测基础 → 检索/回答可靠性与增量更新 → 演示与完整验证 → 项目交接文档。

## 事实边界

- 历史版本用于固定实验快照，不称为最新版，也不从快照年份推断当前产品行为。
- 候选问题即使原文锚点校验通过，也不等于人工确认答案正确、完整或具有代表性。
- 真实模型密钥由用户在本地 `.env` 配置；没有成功请求和报告时，不声称真实模型验证完成。
- 重排模型须在基线和困难样例成立后再决定是否加入；本轮不预先声称它能改善效果。
- 不执行生成的运维命令，也不连接真实企业系统；当前是技术支持建议与证据检索工具。
